公開されている企業の IR データを分析するのに、どのくらいの計算が必要なのかを、手元で測った数字をもとに整理してみます。使っているのは RTX PRO 6000（VRAM 96GB）1 枚で、消費電力の上限は 370W にしています。

## データの量

| データ | 期間 | 件数 |
| --- | --- | --- |
| TDnet の適時開示 | 2016年1月〜2026年5月 | 約 65 万件 |
| 　うち決算短信 | 同上 | 154,274 件 |
| 　うち業績予想の修正 | 同上 | 47,456 件 |
| 　うち中期経営計画 | 同上 | 7,213 件 |
| EDINET の有価証券報告書 | 11 年分 | 75,737 件 |
| EDINET の四半期報告書 | 同上 | 95,493 件 |
| EDINET の半期報告書 | 同上 | 17,592 件 |

ファイルの大きさは思ったより小さく、有価証券報告書の zip は 1 件あたり平均 98KB でした（2025年6月分の 3,142 件で 308MB）。PDF はもう少し大きく、トヨタの開示資料 347 件で 130.5MB、1 件あたり平均 376KB です。保存する容量はそれほど問題になりません。

大きくなるのは、XBRL から取り出した数値を全部ためたときで、今は 3.17 億行、100GB になっています。

## LLM が要らない部分

決算短信や有価証券報告書の数値は XBRL で取れるので、ここには LLM を使っていません。普通のパースで済みます。

LLM が必要になるのは、PDF にしか書かれていない情報を読むときです。たとえば XBRL がない業績予想の修正（16,004 件）、中期経営計画、決算説明資料などです。

## 測った数字

### PDF からの抽出

業績予想の修正の PDF から数値を抜き出す処理を、vLLM で Qwen3-30B-A3B を動かして測りました。8 並列で 1 秒あたり 0.5 件（370 件で測定）です。16,004 件すべてだと約 9 GPU 時間になります。

## 見積もってみる

上の数字を使うと、たとえば次のようになります。

- **中期経営計画 7,213 件**：PDF 抽出と同じ 1 秒あたり 0.5 件なら、約 4 時間です。GPT-4 や Claude の API を使った場合の見積もりは 1 件 10〜50 円で、全部で 7 万〜36 万円になります。
- **決算短信 154,274 件をすべて LLM で読む場合**：同じ速さなら約 86 時間、3 日半ほどです。実際には XBRL で数値が取れるので、ここまでする必要はありません。

手元の GPU で 4 時間動かしたときの電気代は、370W で約 1.5kWh なので、1kWh 31 円として 50 円ほどです。（電気代の単価は目安です）

データの量だけを見ると、公開されている IR データは個人の GPU 1 枚でも十分に扱えます。時間がかかるのは PDF を LLM で読む部分です。

## まだわかっていないこと

- 決算短信、有価証券報告書、決算説明資料の、1 件あたりのトークン数はまだ測っていません
- 精度の問題があります。中期経営計画の抽出は正解率 95% という基準に届かず（93%、91%）、全件はまだ回していません
